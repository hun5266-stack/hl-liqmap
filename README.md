# hl-liqmap

하이퍼리퀴드 BTC 청산가 스냅샷 수집기.

## 왜 만들었나

청산가가 실제로 지지/저항으로 쓰이는지 검증하려면 **가격이 그 자리에 도달하기 전에 찍어둔 지도**가 필요하다.
하이퍼리퀴드 API는 현재 상태만 주므로 과거 시점의 지도를 소급해서 만들 수 없다. 지금부터 쌓는 수밖에 없다.

이미 일어난 청산 기록으로는 검증이 안 된다. 청산은 가격이 간 자리에서 일어나므로
"가격이 왔던 곳에 청산이 있었다"는 동어반복이다. 스냅샷 시점과 가격 행동이 분리돼야 한다.

## 어떻게 모으나

집계된 청산맵 API는 없다. 계정별 `clearinghouseState` 응답에 `liquidationPx` 가 들어 있고,
이것을 주소 수만 개에 대해 조회한 뒤 가격대별로 합산한다. 청산가 계산은 하이퍼리퀴드가 한다.

```
① GET  stats-data.hyperliquid.xyz/Mainnet/leaderboard      → 주소 약 44,000개
② POST api.hyperliquid.xyz/info  {"type":"clearinghouseState","user":"0x…"}
③ 응답의 liquidationPx 만 추출해 가격대별 집계
```

두 모드로 돈다.

| 모드 | 대상 | 소요 | 주기 |
|---|---|---|---|
| `--full` | 리더보드 전체 약 44,000개 | 약 18분 | **매시 05분** |
| 기본 | `holders.json` 의 BTC 보유 계정 | 약 70초 | 수동 실행용 |

매시간 전수로 돈다. 신규 진입 계정이 지연 없이 반영된다.

**공개 레포라서 가능하다.** GitHub Actions 무료 분은 공개 레포에 한해 제한이 없다.
비공개였다면 매시간 전수가 월 14,400분으로 무료 한도 2,000분의 7배가 되어
월 $99가량이 청구됐을 것이다.

## 왜 이 주기인가

8/25 스냅샷을 4일 뒤 재조회해 측정한 결과다.

- 포지션 소멸 **19.3%** (하루 약 5%)
- 살아남은 것 중 청산가가 2% 이상 이동한 비율 **48.4%**
- 총 물량 **−14.1%**

절반이 4일이면 못 쓰게 된다. 1시간 간격이면 스냅샷 사이 변화가 0.5% 수준이라
가격이 클러스터에 닿기 직전 상태를 잡을 수 있다.

## 저장 형식

`data/YYYY-MM/YYYYMMDDTHHMM.csv.gz` — 전수 스캔은 `_full` 접미사가 붙는다.

첫 줄이 메타(실행 시각·가격·모드·건수·소요), 둘째 줄이 헤더, 이후가 포지션이다.

**필터를 두지 않고 BTC 포지션을 전부 담는다.** 3주를 모으는 동안 가격이 15~20% 움직이면
오늘 먼 청산가가 나중엔 가까워진다. 그때 데이터가 없으면 소급이 안 된다.
전량 저장해도 스냅샷이 120KB 남짓, 월 80MB 수준이라 아낄 이유가 없다.

`latest.json` 에 최근 스냅샷 요약이 남는다.

**실행 시각을 반드시 기록한다.** GitHub Actions 스케줄은 정시를 보장하지 않고
부하에 따라 수 분에서 십수 분 밀린다. 나중에 보정하려면 실제 시각이 필요하다.

## 검증 설계

데이터를 보고 나서 해석을 정하면 유리한 쪽으로 끌려간다. 기준을 먼저 적어둔다.

시점 **T** 의 지도에서 클러스터를 찍고, **T 이후** 가격이 그 자리에 도달했을 때를 본다.

| 가설 | 예상 결과 |
|---|---|
| 지지/저항으로 작동 | 클러스터에서 반전, 통과 못 함 |
| 가속 구간 | 클러스터를 평소보다 빠르게 통과 |
| 무의미 | 클러스터 여부와 가격 행동이 무관 |

세 번째가 나올 가능성도 충분하고, 그것도 답이다.

두 가지를 지켜야 한다.

- **대조군.** 클러스터 구간만 보면 안 되고 청산이 없는 구간과 비교해야 한다.
- **매물대와 분리.** 청산 클러스터가 거래량 매물대와 겹치는 자리의 반전은 원인을 가릴 수 없다.
  겹치지 않는 구간을 따로 봐야 청산가 고유의 효과가 나온다.

이론적으로 청산가는 지지가 아니다. 그 자리에서 강제 매도가 나오므로 가격을 밀어낸다.
다만 물량이 소진되면 압력이 즉시 사라져 반등이 나온다. "지지"가 아니라 "가속 후 반전 구간"에 가깝다.

## 한계

- **하이퍼리퀴드 한 거래소다.** BTC 미결제약정이 바이낸스의 약 3분의 1이며
  바이낸스·바이빗 포지션은 조회 자체가 불가능하다. 전체 시장 청산 지도가 아니다.
- 리더보드에 집계된 계정만 조회한다. 거래 이력이 없는 계정은 빠지지만 포지션도 없으므로 영향은 없다.
- 크로스 마진 계정의 청산가는 그 포지션이 아니라 **계정 전체 담보** 기준이다.
  "여기서 이 포지션이 터진다"가 아니라 "여기서 이 계정이 무너진다"로 읽어야 한다.

## 수동 실행

```
python collect.py          # 명단 재조회
python collect.py --full   # 전수 스캔 후 명단 갱신
```

Actions 탭의 `collect` 워크플로에서 `workflow_dispatch` 로도 돌릴 수 있다.
